# YuYuan Pass System 产品说明书

> 文档版本：1.3｜应用版本：2.9.2｜更新时间：2026-08-13

## 1. 产品概述

### 1.1 产品名称

YuYuan Pass System（资产管理中心）。

### 1.2 产品定位

面向企业内部行政、IT、运维、财务和综合管理场景，统一管理资产生命周期、发票与流水、知识文档、个人日程、常用站点和内部公告。系统通过可视化统计、角色权限、操作审计、对象存储和可恢复后台任务，提高企业内部数据的准确性、可追溯性与协作效率。

### 1.3 核心价值

1. 建立统一、可查询、可审计的资产台账。
2. 用标准业务单驱动资产状态，减少手工改状态导致的数据失真。
3. 将发票证据、识别结果、人工审核、验真和统计串成闭环。
4. 集中文档、站点、公告和个人日程，减少工作入口分散。
5. 通过 RBAC、API 权限、操作日志和登录日志保证系统可管可查。
6. 通过 Docker Compose 和发布验收脚本形成可重复交付链路。

## 4. 功能范围

### 4.1 首页驾驶舱

首页集中呈现：

- 资产健康度与关键价值指标。
- 最近登记资产。
- 资产流转草稿或待办摘要。
- 个人工作日程摘要。
- 亮色/暗色、响应式导航和减少动态效果。

首页目标是回答“当前资产情况怎样、最近发生了什么、今天需要做什么”，不是替代各业务模块的完整统计。

### 4.2 资产可视化

资产统计包括：

- 档案数量与实物数量。
- 分类数量。
- 资产原值、当前估值和价值减少额。
- 分类价值与分类数量。
- 资产状态构成。
- 资产位置排行。
- 最近登记资产。

### 4.3 资产分类与位置

分类支持名称、编码、颜色、说明、排序和启停。

分类管理同时维护六类位置字典：入库、使用、调入、归还、维修和处置。位置支持编码、说明、排序与启停；停用位置不会出现在新业务单选项中，但历史单据保存文本快照，不受字典后续变化影响。

### 4.4 资产档案

每条资产档案可记录：

- 资产编号、名称和分类。
- 品牌、型号、序列号。
- 数量、单位、采购单价、原值和当前估值。
- 状态、位置和保管人。
- 供应商、购置日期、质保日期。
- 多张照片和备注。

系统按“数量 × 采购单价”计算资产原值。新建资产默认待入库，必须通过入库单后才成为闲置资产。

### 4.5 资产流转

入库、领用、调拨、归还、维修和报废使用统一业务单模型，包含业务日期、目标位置、目标保管人、原因、备注和资产明细。

核心规则：

- 草稿可编辑和删除，不修改资产。
- 单张单据最多选择 100 项资产。
- 提交时锁定资产，在事务内校验状态并更新档案。
- 每次提交写入不可变前后快照。
- 报废后资产进入 `retired`，当前估值归零。
- 已产生正式流转记录的资产不能直接删除。
- 当前以整条资产档案为流转单位，不支持部分数量拆分。

### 4.6 发票识别与流水

流水管理包含：

- 发票单文件或批量上传。
- 原始证据文件存储。
- OCR/多模态识别任务与失败重试。
- 发票代码、号码、日期、购销方和金额字段复核。
- 发票验真、差异记录和验真历史。
- 发票确认、管理员重开和已确认防重。
- 发票分类、分类规则与自动分类。
- 流水总览和正式台账。

只有 `confirmed` 发票进入正式统计。金额使用整数“分”存储，避免浮点累计误差。识别和验真能力依赖部署环境配置的提供方，系统可通过能力接口展示当前可用状态。

### 4.7 文档中心

文档中心提供：

- 文件上传和对象存储。
- Word、Excel、PDF、Markdown 和文本预览。
- Markdown、文本、富文本和 Excel 在线编辑。
- 标题、备注和在线内容保存。
- 原始文件读取和删除。

原始证据文件与在线编辑内容分开保存，在线保存不会覆盖原文件。列表只返回轻量元数据，避免批量加载正文。

### 4.8 工作日历

个人工作日历提供：

- 月历浏览、当天日程和快速新增。
- 标题、日期、时间、类型和备注。
- 每日、每周、每月重复规则。
- 旧浏览器本地日程的一次性导入。
- 持久化提醒收件箱、单条已读和全部已读。

日程数据按用户隔离，服务端从登录身份确定归属，不接受客户端指定其他用户。

### 4.9 站点收藏

支持维护常用 HTTP/HTTPS 工作入口：名称、URL、分类、说明、颜色、排序和启停。打开站点会累计访问次数并更新最近访问时间。

### 4.10 公告中心

公告支持草稿、发布、编辑、删除、附件、通知列表和跨设备已读状态。发布后在线用户通过 SSE 收到提醒；离线用户下次登录后仍能看到未读公告。

### 4.11 媒体库

媒体库只接受图片，用于头像、资产照片、文档插图和登录外观。文件统一进入 S3 兼容对象存储，生产环境由服务端最终校验格式、MIME 和大小。

### 4.12 服务器负载

监控页面按选定周期采集并展示 CPU、内存、系统负载、磁盘、主机、内核、Go runtime、Goroutine、运行时长和当前页面内的最近趋势。

### 4.13 登录外观

登录外观支持：

- 上传并应用登录图标，或恢复默认图标。
- 维护登录背景图库。
- 选择并激活背景。
- 删除未使用背景。

当前登录图标和背景通过公开只读接口提供给登录页，写操作受管理员 API 权限和操作审计保护。

### 4.14 权限与审计

- 用户、角色、菜单、API 和按钮权限。
- JWT 登录和 Casbin 路径/方法授权。
- 关键写操作记录。
- 登录日志、错误日志和业务审计快照。
- API Token、字典、参数、版本和运行配置管理。

## 5. 核心业务流程

### 5.1 资产建档与入库

```mermaid
flowchart LR
    A["新建资产档案"] --> B["状态 pending_inbound"]
    B --> C["创建入库单草稿"]
    C --> D["提交入库单"]
    D --> E["状态 idle，写入位置"]
    E --> F["生成流转快照"]
```

### 5.2 资产领用与归还

1. 从符合状态的资产中选择明细。
2. 领用必须填写责任人，可填写目标位置。
3. 提交后状态为 `in_use`。
4. 归还必须填写目标位置，提交后状态为 `idle` 并清空保管人。

### 5.3 发票处理

```mermaid
flowchart LR
    A["上传文件"] --> B["uploaded / recognizing"]
    B --> C["pending_review"]
    C --> D["人工复核"]
    D --> E["验真（可用时）"]
    E --> F["confirmed"]
    F --> G["正式统计"]
```

识别失败进入 `recognition_failed`，可重试。已确认发票如需修改，由管理员重开为待复核状态。

### 5.4 文档协作

1. 上传原始文件。
2. 查看源文件或预览。
3. 对支持格式点击开始编辑。
4. 保存在线版本、标题和备注。
5. 原文件保持不变，可随时重新读取。

### 5.5 公告发布

1. 编辑标题、正文和附件。
2. 保存草稿或发布。
3. 已发布公告进入通知收件箱。
4. 在线用户经 SSE 接收，离线用户登录后补偿读取。
5. 用户查看后写入个人已读记录。

### 5.6 日程提醒

1. 用户创建一次性或重复日程。
2. 后台任务计算到期发生项。
3. 以“用户 + 日程 + 发生时间”幂等生成提醒。
4. 用户单条或全部标记已读。

## 6. 数据口径

### 6.1 资产状态

| 状态 | 中文 | 进入方式 |
| --- | --- | --- |
| `pending_inbound` | 待入库 | 新建档案 |
| `idle` | 闲置 | 入库或归还 |
| `in_use` | 使用中 | 领用 |
| `maintenance` | 维修中 | 维修 |
| `retired` | 已处置 | 报废 |

调拨保持原状态，只改变位置和可选保管人。

### 6.2 发票状态

| 状态 | 中文 |
| --- | --- |
| `uploaded` | 已上传 |
| `recognizing` | 识别中 |
| `pending_review` | 待复核 |
| `confirmed` | 已确认 |
| `recognition_failed` | 识别失败 |

### 6.3 金额口径

- 资产原值 = 数量 × 采购单价。
- 资产价值减少额 = 原值 - 当前估值。
- 发票金额、税额和价税合计以整数分持久化，页面转换为元展示。
- 只有已确认发票进入正式流水统计。

### 6.4 文件存储

- 资产图片、发票证据、文档源文件和登录背景存储于 S3 兼容对象存储。
- 数据库保存对象 key、元数据和业务关联。
- 私有证据文件通过后端权限校验后读取。
- 发票删除通过持久化清理任务补偿对象删除。

## 7. 非功能要求

### 7.1 安全

- 生产环境必须修改管理员密码、JWT key 和外部服务凭据。
- PostgreSQL、Redis 和对象存储不得直接暴露公网。
- Web/API 通过 HTTPS 反向代理对外提供。
- 文件上传执行格式、MIME、大小和路径校验。
- 权限判断以服务端身份和策略为准。

### 7.2 性能

- 列表接口分页。
- 大字段不进入轻量列表。
- 大文件在用户明确编辑时解析。
- 仪表盘使用服务端聚合。
- 前端静态哈希资源长期缓存，HTML 入口不缓存。

### 7.3 可用性

- 桌面与移动端基础可用。
- 支持亮色、暗色、可见焦点和减少动画。
- 页面提供加载、空数据、失败和无权限状态。
- 状态信息不能只用颜色区分。

### 7.4 可维护性

- 业务功能优先使用插件结构。
- 业务规则集中于 Service。
- API、数据、部署变更同步维护文档。
- 发布以 Git commit 为唯一追踪标识。

## 9. 产品边界

当前版本尚未形成完整业务闭环的能力：

- 资产盘点、二维码/RFID 标签和盘盈盘亏。
- 资产折旧会计、维修费用和审批流。
- 采购、供应商、合同和库存供应链。
- 正式财务凭证、报销和 ERP 接口。
- 团队共享日历、参与人和多渠道提醒。
- 多人实时文档协作和企业全文检索。

这些能力不以空菜单展示，后续应在领域模型、权限、状态和验收口径明确后分阶段开放。

## 10. 验收建议

### 10.1 业务验收

- 资产六类流转覆盖允许与拒绝状态。
- 草稿不修改资产，提交后资产与快照一致。
- 发票识别失败可重试，待复核可编辑，确认后防重生效。
- 已确认发票必须先重开才能修改。
- 文档原文件与在线内容互不覆盖。
- 公告在线通知和离线未读均可恢复。
- 日程重复规则不重复生成同一发生项通知。
- 非管理员无权调用未授权 API。

### 10.2 部署验收

- Web、API 和 `/api` 代理链路正常。
- PostgreSQL、Redis、对象存储连接正常。
- 首次初始化和重复启动均可执行。
- 缺失静态资源返回 404，不回退为 HTML。
- 容器重启后数据、文件和运行配置保持不丢失。
- `release-acceptance.sh` 返回 0 后才能标记上线成功。
