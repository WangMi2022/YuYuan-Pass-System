# 安全修复计划（不含 HTTPS/TLS）

- **计划日期**：2026-08-16
- **对应报告**：`docs/SECURITY_AUDIT_2026-08-16.md`
- **目标**：关闭应用、API、文件、AI、依赖和部署暴露面风险；不处理 HTTPS/TLS。

## 1. 执行原则

1. 先封堵可匿名利用和跨业务数据边界，再做依赖和架构升级。
2. 每项修复必须有“代码变更 + 回归测试 + 运行时验收 + 回滚方式”。
3. 不把对象 key、前端隐藏字段或路由地址当作授权边界。
4. 所有配额、限流和审计策略按用户、租户、IP、接口和模型维度可观测。
5. 依赖升级采用小批次、锁定版本、可回滚发布；不使用浮动镜像标签。

## 2. 优先级与排期总览

| 优先级 | 时间窗口 | 目标 | 对应风险 |
|---|---|---|---|
| P0 | 24–48 小时 | 关闭匿名数据读取、脚本执行、初始化接管和无界资源消耗 | SEC-01、02、03、07、13 |
| P1 | 1 周 | 建立对象完整性、会话撤销、AI 资源与审计边界 | SEC-04、08、09、10、11、12 |
| P2 | 2–4 周 | 完成依赖、镜像、CI 门禁和安全回归体系 | SEC-05、06 及持续治理 |
| P3 | 持续 | 监控、复测、SBOM、应急演练和季度复审 | 全部 |

建议负责人角色：

- **应用后端**：路由、对象授权、初始化、会话、AI 中间件。
- **前端**：依赖升级、富文本/表格/图表输入清理、XSS 回归。
- **平台/运维**：端口、Swagger、镜像 digest、密钥注入、日志和告警。
- **安全/QA**：攻击用例、依赖复扫、验收证据和复测报告。

## 3. P0：24–48 小时封堵

### P0-1 收紧资产图片代理（SEC-02）

**改动**

- 将 `GET /asset/photo?key=` 改为按资产照片记录取 key 的资源接口，例如 `GET /asset/:assetId/photos/:photoId`。
- 先执行 JWT、租户/部门和 Casbin 校验，再查询照片记录；请求不得携带可直接使用的 OSS key。
- MinIO bucket 设为 private，后端签发单对象、短 TTL 的 presigned URL，或由后端流式代理。
- 对返回 MIME、文件类型、下载/内联行为做白名单控制，并隐藏对象是否存在。

**验收**

- 匿名、无权限用户和跨租户用户均为 403/404。
- 用户 A 的 `photoId`、文档 key、发票 key 不能被用户 B 读取。
- URL 编码、路径规范化、重复参数和伪造 `key` 均不能绕过校验。
- 增加 API 集成测试和至少一条生产合成数据验证记录。

**回滚**：保留旧 handler 的 feature flag，但默认关闭；回滚只恢复接口版本，不恢复公开任意 key 读取。

### P0-2 禁止 SVG 或转为安全位图（SEC-03）

**改动**

- 立即从通用上传允许列表移除 `.svg`、`image/svg+xml`。
- 若业务必须展示 SVG，服务端采用白名单 sanitizer 或栅格化为 PNG/WebP；禁止 `script`、事件属性、`foreignObject`、外链和危险 URL。
- 静态文件迁移到独立 origin/不可执行域名，响应设置正确 `Content-Type`、`Content-Disposition` 和 `X-Content-Type-Options: nosniff`。
- 规划将长期 token 从 localStorage 迁移到 HttpOnly、Secure、SameSite Cookie 或短时内存 token。

**验收**

- 恶意 SVG fixture 上传被拒绝或生成无脚本位图。
- 浏览器访问历史样本不会执行脚本、发起外连或读取 token。
- 本地存储、MinIO 代理和 CDN（如有）三种访问路径分别验证。

**回滚**：保留原始文件但不公开执行；若必须恢复展示，只允许下载，不恢复同源 `image/svg+xml` 内联。

### P0-3 锁死初始化接口（SEC-01）

**改动**

- 部署阶段生成一次性高熵 `INSTALL_TOKEN`，仅在 `INSTALL_MODE=true` 时注入。
- 初始化成功后写入不可逆安装标记；令牌使用一次即失效，并设置短期过期时间和失败次数上限。
- 路由增加 loopback/管理网段限制、Origin/CSRF 校验和审计；生产代理默认不转发 `/init/*`。
- 启动时检测默认 JWT secret，发现 `qmPlus` 等样例值直接失败。

**验收**

- 当前已初始化实例的初始化请求始终拒绝。
- 新实例无令牌、过期令牌、重复令牌和非管理来源均拒绝。
- 并发提交只允许一个成功，数据库配置原子写入。

**回滚**：仅在隔离安装环境通过运维开关恢复，不在生产环境关闭安装标记或开放公网访问。

### P0-4 关闭生产 Swagger 并收窄监听（SEC-07）

**改动**

- 生产配置关闭 Swagger，或增加管理员认证和管理网段 allowlist。
- Compose 端口从 `0.0.0.0:8888` 改为 `127.0.0.1:8888`，由反向代理转发必要路径。
- 健康检查单独提供最小信息端点，禁止返回版本、配置和堆栈。
- 防火墙只开放反向代理入口和必要的管理网段。

**验收**

- 外部访问 Swagger 为 404/403，内部管理访问按预期工作。
- 外部无法直连 8888，反向代理业务请求与健康检查正常。
- 端口扫描和容器端口映射记录留档。

**回滚**：先只回滚监听绑定，不恢复匿名 Swagger；异常时通过管理网段临时启用并设置过期时间。

### P0-5 给通用上传加硬限制（SEC-13）

**改动**

- 设置请求体、单文件、批量、用户/租户日配额；默认单文件不超过 10 MB，具体值通过配置管理。
- 使用流式 `MaxBytesReader`/受限 reader，不信任客户端 `Content-Length`。
- 上传到临时对象，完成类型、大小、病毒/恶意内容检查后原子提交；失败和超时清理临时对象。
- 增加速率限制、并发上传上限和存储使用告警。

**验收**

- 超限文件在进入持久化前被拒绝，返回稳定错误码。
- 断开连接、超时、重复提交不会留下可访问临时对象。
- 并发压测下 CPU、内存、带宽和对象数量均受控。

**回滚**：通过配置临时降低而非取消限制；保留上传接口版本，禁止恢复无上限行为。

## 4. P1：一周内完成边界治理

### P1-1 重新设计对象 key，禁止覆盖（SEC-04）

**改动**：统一为 `业务/租户/日期/UUID.ext`；原文件名只做展示；创建使用不覆盖语义；数据库保存内容 hash、MIME、大小、版本和操作者。

**验收**：同名并发上传 100 次无覆盖；旧对象内容 hash 不变；冲突历史对象完成盘点和隔离。

### P1-2 接入 token 版本与即时撤销（SEC-08）

**改动**：用户增加 `securityVersion`；JWT 携带版本；禁用、删除、改角色、重置密码时递增；中间件校验并保留高风险黑名单。

**验收**：管理动作完成后旧 token 下一请求即失效；正常请求延迟、Redis/DB 查询量有基线对比。

### P1-3 Copilot 使用专用审计（SEC-09）

**改动**：智能路由移除通用 `OperationRecord()`，接入 `AIOperationRecord`；只保留 hash、模型、租户、耗时、token、结果码和风险标签；正文加密、最小权限、短保留期。

**验收**：通用操作日志和后台列表不出现问题/回答正文；安全审计可按 hash 关联调用，但不能反解正文。

### P1-4 接入 AI 限流、配额和 SSE 并发（SEC-10）

**改动**：统一走 AI Gateway；按用户、租户、IP、模型和接口配置 QPS、并发、日 token/费用配额；SSE 设置连接超时、最大输出、断开清理和全局并发。

**验收**：阈值外稳定返回 429/430；SSE 断开释放连接、goroutine、游标和模型请求；账单与审计可对账。

### P1-5 收紧错误日志和 Casbin 刷新（SEC-11、SEC-12）

**改动**：错误上报改为受控令牌或认证接口；限制频率、字段长度、每日额度并清理 HTML/控制字符；Casbin 刷新移入管理员私有路由，加入最小间隔、分布式锁和缓存。

**验收**：匿名批量错误和策略刷新均被拒绝/限速；管理员操作幂等；数据库增长和 CPU 负载在预算内。

## 5. P2：2–4 周依赖与供应链治理

### P2-1 前端依赖升级与替换（SEC-05）

**顺序**

1. 升级 `axios` 到审计建议安全版，回归登录、刷新 token、上传和下载。
2. 评估 `echarts 5.5.1 → 6.1.0` 的主版本迁移，重点测试图表、富文本 tooltip 和导出。
3. 隔离/替换无修复的 `x-data-spreadsheet`、`xlsx`、`wangeditor` 链路；过渡期加入 sanitizer、Worker、文件复杂度上限和页面隔离。
4. 禁止 `vue3-sfc-loader` 加载不可信 SFC，升级 compiler/PostCSS 链并加入 CSP/沙箱。
5. 提交 lockfile，CI 使用 `npm ci --ignore-scripts`（按项目构建需要评估脚本白名单），固定 Node 镜像。

**验收**：`npm audit --omit=dev` 的 critical/high 为 0，或每个例外都有书面风险接受、影响路径和到期日；XSS fixture、恶意表格和富文本回归通过。

### P2-2 Go 版本与模块升级（SEC-06）

**顺序**

1. 固定到包含修复的受支持 Go patch 版本，更新 `server/go.mod` 和 Docker 基础镜像 digest。
2. 升级 `excelize`、S3 SDK、`x/text`、`x/net`、`xz`、`go-redis`、`pgx` 到审计建议或更高兼容安全版。
3. 为 Excel、压缩包、远程响应设置大小、深度、耗时和并发限制。
4. 运行单元、集成和构建测试，重新执行 `govulncheck ./...`；补充可复现 `gosec` 容器/二进制扫描。

**验收**：`govulncheck ./...` 无高风险可达漏洞；依赖变更有 SBOM、lock 记录和回滚镜像；恶意工作表/压缩包 fixture 不会 OOM/Panic。

### P2-3 供应链与镜像基线

- 所有基础镜像使用 digest，不使用 `golang:1.24-alpine` 等浮动标签。
- CI 生成 SBOM，保存构建来源、依赖锁文件和镜像 digest。
- 依赖更新通过 PR 自动扫描；critical/high 阻断发布，例外需安全负责人批准。
- 禁止把 `.env`、`config.yaml`、密钥、数据库 dump 和对象存储凭据写入仓库、日志或归档。

## 6. P3：持续控制与监控

### 6.1 监控指标

- 403/404 对象访问失败率、跨租户访问告警、对象 key 不存在探测。
- 初始化接口命中次数、失败次数、令牌使用审计。
- 上传拒绝率、用户/租户配额、临时对象遗留量和存储增长率。
- AI 每用户/租户 token、费用、QPS、SSE 并发、超时和 429 比例。
- 依赖扫描新漏洞、镜像 digest 漂移和 Swagger/8888 外部可达性。

### 6.2 安全回归套件

- 路由授权矩阵：匿名、普通用户、部门管理员、超级管理员、跨租户。
- 对象访问：伪造 key、URL 编码、路径变体、跨业务对象和并发覆盖。
- 文件安全：SVG、HTML、双扩展名、超大文件、恶意压缩包、Excel 公式/宏。
- 会话安全：禁用、删除、改角色、改密码后的旧 token。
- AI 安全：提示词/回答不落通用日志、配额、SSE 断开和模型预算。
- 依赖门禁：`npm audit --omit=dev`、`govulncheck ./...`、补充 `gosec`。

## 7. 发布与回滚流程

1. 每项修复先在隔离环境使用合成数据验证，不直接对生产对象做破坏性测试。
2. 变更拆成小提交，记录对应 SEC 编号和回归证据。
3. 发布前检查 `git diff --check`、依赖扫描、构建、数据库迁移兼容性和配置默认值。
4. 生产先灰度一台/一个实例，观察 15–30 分钟指标，再逐步扩大。
5. 失败时回滚到上一个已验证镜像/提交；保留数据库向前兼容迁移和对象 key 双读期。
6. 发布后执行匿名/有权/无权三组探测，保存响应码、审计事件、容器状态和依赖报告。
